这个博客正在重新整理

把上一版那股 AI 味洗掉：删掉发光球、双语标签和卡片套娃，换成克制、统一、零依赖的深色排版。顺便记下这次整理本身——它就是一个「把过程留下来」的例子。

第一部分：为什么

学 AI 的过程很容易忘。不是忘了知识，是忘了当时为什么那么做：某个插件为什么装、某个配置为什么改、某个报错后来怎么解决的。过两周再看，只记得结果，不记得过程。

而这个博客上一版的问题，恰好是同一个毛病——只看得到「做成什么样」，看不到「为什么这么做」。发光球、双语标签、卡片套娃，堆得很满，但没有一条说清楚设计判断。

所以这次整理定了一条规矩：正文只写 HTML 读不出来的东西。

把想法写下来，才知道自己到底想没想清楚。

第二部分：怎么做

正文用 <p>。强调某个词用 strong，不要用颜色堆。链接这样写：一个真实的链接。引用用 blockquote。

代码块用 pre > code，例如：

git clone https://github.com/Torricelli0/torricelli0.github.io.git
cd torricelli0.github.io
git add . && git commit -m "new post" && git push

这次整理还做了三件具体的事：

  1. 首页标签云改成真实统计——以前 AI 12 / Agent 9 是手写的假数字，现在跑脚本扫描每篇文章的 meta tags 自动生成
  2. 删掉首页里指向 #about 的假条目——看起来像文章，点开什么都没有
  3. 把 git remote 从 HTTPS 换成 SSH——HTTPS 推送时 token 失效，本机 SSH key 才是可用的那条路

最后：踩坑

整理过程中真实遇到的问题，比任何排版技巧都值得记：

一是缓存。push 成功后线上标签还是旧数字，加了时间戳参数才看到新的。GitHub Pages 的 CDN 有延迟，「没更新」和「没生效」是两回事。

二是锁。WorkBuddy 插件保存设置时报 timed out waiting for the writer lock——两个进程同时写 package.json，一个卡住，另一个就只能超时。

三是路径。本地 HTML 发给别人打不开，多半是写了绝对路径。/files/a.png 只在你机器上有意义；./images/a.png 跟着文件夹走；data:image/png;base64,... 才是真正嵌进文件里。

这些坑不记下来，下次还得再踩一遍。这就是我把博客重新整理的原因。
